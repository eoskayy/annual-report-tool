# Standing project rules

- Work in English. Follow the recorded assignment requirements, logs/prompts/general_instructions.txt, and logs/prompts/project_instructions.txt; the project instructions update the general instructions. The original assignment PDF was removed from the submission at the user’s request. Read data/README.md for provenance, definitions, units, and unresolved data questions.
- Never modify anything in data/raw/. Use only uploaded reports. Never expose API keys or personal data; preserve originals. User-reported permission and privacy assurances are recorded in logs/setup_log.md, not independently verified.
- Build and evaluate a simple, script-based annual-report comparison tool. The selected question concerns extraction accuracy and consistency; automotive reports are pilot inputs. No website, database, multi-agent system, added metrics, sectors, or report downloads without approved expansion.
- Follow the agreed evaluation plan before financial extraction. Use revenue and each printed profit-measure label; name margins after that label. Keep definitions configurable. Separate development from evaluation and disclose any test-report reuse.
- Follow plan.md. Ask before changing it and log every analytical choice. Explain substantive supervised steps and wait for approval; autonomous work stays within the agreed plan and stopping conditions. Keep scripts, outputs, and decisions for both runs separate.
- After every filter, merge, or drop, print row counts before and after and the reason. Check merge keys and unexpected duplication. Number scripts in execution order; record dependencies and execution instructions.
- Every analytical number in a write-up must come from a file in results/; name its generating script. Keep extracted values separate from calculations. Retain filename, company/year, PDF/printed pages, table/section, exact label, value, currency/units, scope, and reported/adjusted/restated status.
- The extraction script must read financial values directly from the PDFs at run time. Never type financial values by hand into scripts, JSON files, or configuration files; never use the user’s reference answers as extraction inputs.
- The user keeps the completed reference table outside the project until both runs are frozen. Do not search for it or ask for it before then. The autonomous chat must not read src/supervised/, results/supervised/, or logs/supervised/; follow the clean-copy restrictions in plan.md for the separate fresh-session comparison.
- Prefer audited consolidated statements. Never silently substitute another profit measure. Compare compatible periods, scopes, definitions, and units; agree on conversion before comparing monetary amounts across currencies. Never guess: flag missing, ambiguous, or non-comparable figures.
- Fix random seeds where relevant. Log prompts, outputs, available model names/versions, settings, and remaining variability. State when exact details are unavailable; do not claim hidden platform information.
- No causal claims unless the design supports them. Say "I am not sure" when uncertain. Separate facts, assumptions, exploratory findings, and advance-specified tests. Always show accuracy denominators and describe the small sample as pilot evidence.
- Guide the user through three independent claim checks and independent headline-result recomputation; wait for their actual evidence. Arrange a genuinely fresh-session or different-model comparison. Never label agent rechecks as user verification.
- Record actual mistakes only in mistakes.md, with evidence, correction, conclusion impact, and lessons; distinguish suspected issues. Save enough context to resume, and distinguish planned, agent-completed, and user-verified work. Guide one meaningful step at a time and stop at agreed boundaries.

- Validate runtime statement/year/group selection and row-cell counts; distinguish note references from values. Use the annual-period constraint on actual document date candidates. Abstain with reasons/candidates for undecidable fields; stop for unresolved page, column, or value-cell location.
- Keep observed printed-page numbers separate from PDF metadata labels; verify structural title numbers directly and mask observed glyph encodings as well as digits. Use the logged bundled Python and pinned PDF dependency.
- Never revise frozen primary outputs. Save post-results supplementary analyses separately, label them exploratory, and state definition/period assumptions. Report user verification as user-reported unless independently audited; preserve first-pass evidence.
